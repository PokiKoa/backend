# ADR-002: Contrato API v2 (`/api/v1/`) y cambio de nombres respecto a la v1

- **Estado:** Aceptado
- **Fecha:** 2026-11-02

## Contexto

En la versión académica v1 (`entrega2`), todos los modelos, campos, endpoints y respuestas JSON estaban en español, con múltiples alias redundantes en `BebeSerializer` (`cuna`, `numero_cuna`, `cuna_identificador`, `medico_nombre`, `medico_responsable`, `canula_ok`, `estado_canula`), sin versionado de rutas (`/api/bebes/`) y con formatos de error heterogéneos (`{"error": "..."}` vs. `{"detail": "..."}`).

## Decisión

1. **Idioma de código y contrato JSON:** Todos los identificadores de código, nombres de tablas/modelos, campos JSON y rutas REST pasan a **inglés**. Los mensajes de error, validaciones y textos clínicos orientados al usuario se entregan en **español** (`LANGUAGE_CODE = "es-cl"` / `"es"`).
2. **Versionado de API:** Todas las rutas se exponen bajo `/api/v1/`. El esquema OpenAPI 3.0 se publica en `/api/v1/schema/` y su visor Swagger en `/api/v1/docs/` mediante `drf-spectacular`.
3. **Formato uniforme de errores:** Se configura un `EXCEPTION_HANDLER` global en DRF que normaliza todo error a la estructura:
   ```json
   {
     "error": {
       "code": "validation_error",
       "message": "Los datos enviados no son válidos.",
       "details": {
         "heart_rate": ["La frecuencia cardíaca debe estar entre 1 y 260 lpm."]
       }
     }
   }
   ```
4. **Paginación estándar:** Todos los listados usan `PageNumberPagination` (`page_size = 20`, configurable vía `?page_size=` hasta `100`).

## Mapeo de endpoints (v1 → v2)

| Recurso | Ruta v1 | Ruta v2 |
|---|---|---|
| Salud del servicio | *(no existía)* | `GET /api/v1/health/` |
| Autenticación / Usuarios | `/api/medicos/` | `/api/v1/auth/login/`, `/api/v1/auth/refresh/`, `/api/v1/auth/logout/`, `/api/v1/users/` |
| Pacientes | `/api/bebes/` | `/api/v1/patients/` y `POST /api/v1/patients/{id}/discharge/` |
| Cunas / Dispositivos | `/api/cunas/` | `/api/v1/cribs/`, `POST /api/v1/cribs/{id}/assign-patient/`, `POST /api/v1/cribs/{id}/release/` |
| Ingesta y consulta de telemetría | `POST /api/cunas/{id}/telemetria/` | `POST /api/v1/cribs/{id}/telemetry/`, `GET /api/v1/patients/{id}/vitals/` |
| Alertas | `/api/alertas/`, `/api/alertas/{id}/resolver/` | `/api/v1/alerts/`, `POST /api/v1/alerts/{id}/acknowledge/`, `POST /api/v1/alerts/{id}/resolve/` |
| Catálogo de medicamentos | `/api/catalogo-medicamentos/` | `/api/v1/medication-catalog/` |
| Indicaciones / Administración | `/api/medicamentos/`, `.../administrar/` | `/api/v1/prescriptions/`, `POST /api/v1/prescriptions/{id}/administer/` |
| Planes de cuidado | `/api/planes-cuidado/` | `/api/v1/care-plans/` |
| Observaciones clínicas | *(campo de texto en `Bebe`)* | `/api/v1/observations/` |
| Auditoría | *(no existía)* | `GET /api/v1/audit-logs/` |

## Mapeo de modelos y campos (v1 → v2)

### 1. `Medico` → `accounts.User`
| Campo v1 (`Medico`) | Campo v2 (`User`) | Cambio |
|---|---|---|
| `nombre_completo` | `full_name` | Renombrado a inglés |
| `turno` | `shift` | Enumeración (`morning`, `afternoon`, `night`) |
| *(no existía)* | `email`, `role`, `is_active` | Cuentas autenticadas con roles (`admin`, `neonatologist`, `nurse`, `pharmacist`) |

### 2. `Bebe` → `patients.Patient`
| Campo v1 (`Bebe`) | Campo v2 (`Patient`) | Cambio |
|---|---|---|
| `identificador` | `medical_record_number` | Identificador clínico único (ej. `RN-0001`) |
| `nombre_completo` / `nombre` | `full_name` | Se elimina alias duplicado `nombre` |
| `edad_meses` | `age_days` *(propiedad calculada)* | Se elimina columna estática; se calcula desde `birth_date` |
| `edad_gestacional` | `gestational_age_weeks` | `Decimal(4, 1)` validado en `[20.0, 45.0]` |
| `sexo` | `sex` | `F` / `M` |
| `peso` *(float)* | `birth_weight_g`, `current_weight_g` *(int)* | Enteros en gramos + historial en `WeightRecord` |
| `fecha_nacimiento` | `birth_date` | `DateField` (no futura) |
| `fecha_ingreso` | `admitted_at` | `DateTimeField` |
| `diagnostico` | `diagnosis` | `TextField` |
| `observaciones` | Modelo `ClinicalObservation` | Entidad propia con autor, fecha y categoría |
| `plan_cuidados` | Modelo `CarePlan` | Se unifica en la entidad relacional `CarePlan` |
| `medico_a_cargo` | `attending_physician` | FK a `accounts.User` (`role=neonatologist`) |
| `cuna_asignada` | `crib` | `OneToOneField` a `devices.Crib` |
| *(borrado físico)* | `status`, `discharged_at`, `discharge_outcome`, `discharge_cause` | Baja lógica con conservación de historial |

### 3. `Cuna` → `devices.Crib` + `vitals.VitalSignReading`
| Campo v1 (`Cuna`) | Ubicación y campo v2 | Cambio |
|---|---|---|
| `identificador` | `Crib.code` | Identificador único de cuna (ej. `C-01`) |
| `paciente` | `Patient.crib` (`Crib.current_patient`) | Relación 1:1 hacia el paciente activo |
| `ritmo_cardiaco` | `VitalSignReading.heart_rate` | Se almacena como serie histórica por lectura |
| `spo2` | `VitalSignReading.spo2` | Serie histórica (0–100 %) |
| `temperatura` | `VitalSignReading.temperature` | `Decimal(4, 1)` en serie histórica (25.0–45.0 °C) |
| `estado_sueno` | `VitalSignReading.sleep_state` | `asleep` / `awake` |
| `canula_ok` | `VitalSignReading.cannula_connected` | Booleano estricto |
| `via_iv_activa` | `VitalSignReading.iv_line_active` | Booleano estricto |
| `ultima_actualizacion` | `Crib.last_telemetry_at` / `VitalSignReading.recorded_at` | Sello de tiempo del evento y de la última ingesta |

### 4. `Alerta` → `alerts.Alert`
| Campo v1 (`Alerta`) | Campo v2 (`Alert`) | Cambio |
|---|---|---|
| `paciente` | `patient` | FK a `patients.Patient` |
| `cuna` | `crib` | FK a `devices.Crib` |
| `tipo` | `alert_type` | `heart_rate`, `spo2`, `temperature`, `cannula`, `sensor_fault`, `other` |
| `nivel` | `severity` | `info`, `warning`, `critical` |
| `mensaje` | `message` | Mensaje clínico en español |
| `activa` *(bool)* | `status` | `active`, `acknowledged`, `resolved` |
| `valor_leido` | `measured_value`, `threshold_value` | Guarda valor medido y umbral infringido |
| `fecha_hora` | `triggered_at`, `acknowledged_at`, `resolved_at` | Trazabilidad temporal completa + `acknowledged_by`, `resolved_by` |

### 5. `MedicamentoCatalogo` y `Medicamento` → `medications.MedicationCatalogItem` y `medications.Prescription`
| Campo v1 | Campo v2 | Cambio |
|---|---|---|
| `MedicamentoCatalogo.nombre` | `MedicationCatalogItem.name` | Único en catálogo |
| `MedicamentoCatalogo.principio_activo` | `MedicationCatalogItem.active_ingredient` | Renombrado a inglés |
| `MedicamentoCatalogo.dosis_mg` | `MedicationCatalogItem.concentration_mg` | `Decimal(10, 2) > 0` |
| `MedicamentoCatalogo.stock` | `MedicationCatalogItem.stock` | `CheckConstraint(stock >= 0)` (permite llegar a 0 al agotarse) |
| `Medicamento.nombre` *(texto libre)* | `Prescription.medication` | FK obligatoria a `MedicationCatalogItem` |
| `Medicamento.paciente` | `Prescription.patient` | FK a `patients.Patient` |
| `Medicamento.dosis` | `Prescription.dose` + `units_per_administration` | Permite descontar stock de forma exacta y atómica |
| `Medicamento.via` | `Prescription.route` | `IV`, `IM`, `ET`, `PO`, `SC` |
| `Medicamento.hora` | `Prescription.scheduled_time` | `TimeField` |
| `Medicamento.estado` | `Prescription.status` | `pending`, `administered`, `cancelled` |
| *(no existía)* | `prescribed_by`, `administered_by`, `administered_at` | Auditoría clínica completa de quién prescribe y quién administra |

### 6. `PlanCuidado` → `patients.CarePlan`
| Campo v1 (`PlanCuidado`) | Campo v2 (`CarePlan`) | Cambio |
|---|---|---|
| `bebe` | `patient` | FK a `patients.Patient` |
| `area_cuidado` | `care_area` | Área clínica |
| `intervencion` | `intervention` | Descripción de la intervención |
| `frecuencia` | `frequency` | Frecuencia pautada |
| `estado` | `status` | `active`, `suspended`, `completed` |
